# Circuit Engine implementation status

**Status date:** 2026-11-26

**Current delivery approach:** integrated bulk implementation, not phased milestone delivery. The current work is bounded native-solver integration, not a claim that the entire platform is complete or production-ready.

## Implemented

- Initial provider-neutral deterministic agent tooling offers read-only project summary, circuit schema/topology validation, and declared connectivity operations; opt-in Ollama/OpenAI-compatible model-list probes are restricted to configured loopback endpoints, and a plan-only adapter sends only the explicit user prompt/tool policy, validates read-only calls, then waits for user review; a separate one-time executor verifies the stored plan hash and checks tool outputs, with an optional explicitly requested local-model narrative from compact hashed evidence; the fixed `circuit_review` workflow executes those in sequence and checks identity, topology, and model-hash consistency. A separate circuit-model proposal flow requires schema/topology validation, base-model hash match, expiry, and a one-time explicit approval request before applying. Actions receive bounded hash/timing audit metadata in a 1,000-record hash-linked chain with a verifier; the unsigned chain detects record edits and tail truncation but not a complete rewrite. No autonomous iterative planning loop, authenticated approver identity, or value inference is enabled.
- Portable CMake/C++20 core with typed `Circuit`, `Element`, solver requests/results, standalone CLI, and CTest coverage.
- Native CPU-only C++20 core with dense bounded MNA for linear DC resistor/independent-source circuits, an explicit piecewise-linear diode active-set model, a bounded Shockley diode Newton model (explicit `Is`, ideality, and temperature; parameter/exponent limits and at most 100 voltage-limited iterations). Independent-source sweeps support either diode model separately, but reject mixing (up to 500 elements, 150 non-ground nodes, 180 total unknowns, and 200 sweep points); fixed-step linear RC/RLC backward-Euler transient analysis (up to 100 elements, 24 non-ground nodes, 32 unknowns, and 2,000 steps); and linear R/L/C complex AC sweeps (up to 200 elements, 64 non-ground nodes, 80 unknowns, and 200 frequencies). AC source RMS magnitudes and phases are explicit. Singular, inconsistent, non-finite, nonconvergent, and over-limit requests fail closed.
- Native digital evaluation supports combinational truth tables plus sampled Boolean waveforms with rising- or falling-edge D flip-flops and explicit initial Q. The C++ core validates topology and binary samples; waveform limits are 32 inputs and 10,000 samples. State updates at sample boundaries only; this is not event-driven timing or mixed-signal simulation.
- Versioned C ABI with stable ABI version 1, DC request v1 and legacy DC result v1, expanded DC result v2, DC sweep request/result v1, transient request/result v1, AC sweep request/result v1, digital truth-table request/result v1, and digital-waveform request/result v1. A separate extended waveform-gate struct preserves the pre-existing truth-table gate layout. The expanded DC output includes element voltages, currents, powers, equation/KCL/source residuals, normalized residual, power balance, pivot metrics, and unknown count.
- Python `ctypes` bridge delegates numerical DC operating points, each DC source-sweep point, AC, RC/RLC transient computation, combinational truth tables, and sampled DFF waveforms to C++.
- The project UI exposes explicit-netlist and graph-bound DC source sweeps with selectable node-voltage charts and bounded tables (graph-bound runs require a complete user-supplied model mapping), explicit-netlist and graph-bound AC sweeps with selectable-node magnitude/phase charts (graph-bound sweeps require complete explicit model mappings), and graph-bound RC/RLC transients with selectable node-voltage traces and, for RLC, inductor-current traces; digital APIs have editable explicit-netlist JSON: a half-adder truth-table example, a two-bit modulo-four counter waveform example, output tables/chart, and saved-report access. Existing DC and transient entry points adapt/format native results; graph-bound DC, DC sweep, AC, and transient APIs persist hash-linked reports. The graph mapping, unit conversion, validation, orchestration, and report formatting remain Python-owned. Missing native libraries are explicit errors, not silent Python fallback.
- Typed deterministic single-pole RC synthesis with bounded E-series R/C candidate optimization under explicit cutoff/preferred-resistance objectives, schema-v2 graph output and electrical-model provenance, nominal/tolerance analysis, graph validation, native transient test, request hashing, and opt-in snapshot-aware graph application.
- Initial ESP32 firmware scaffold endpoint for explicitly ESP32-architecture projects: validates caller-supplied GPIO-to-existing-net mappings, emits a hashed generic PlatformIO/Arduino pin-mode starter and manifest, and rejects use for discrete projects. It is deliberately uncompiled and contains no application logic.
- Project backup import now validates bounded ZIP upload/member sizes, portable rooted paths, project/model JSON, graph topology, and snapshot model hashes; files are staged then atomically published under a fresh project ID. The project library exposes an import action. Preserved reports/artifacts are not artifact-specifically validated.
- Regression coverage for native ABI bridges, solver behavior, report contracts, graph mapping, synthesis, API, and schema handling. Unsupported functionality and verification boundaries are stated explicitly.

## Remaining scope and limitations

- C++ core accepts a normalized, indexed circuit snapshot; the canonical schema-v2 project graph, topology mapping, and report orchestration are still Python-managed.
- Dense matrix solving is intentionally bounded. Sparse factorization, controlled sources, semiconductor charge storage, general nonlinear device models, multi-parameter/continuation DC sweeps, adaptive integration, full event-driven digital timing simulation (the current waveform path is sample-driven ideal logic only), and analog/digital mixed-signal co-simulation are not implemented. Inductors are supported as ideal elements in AC and backward-Euler transient analyses; DC operating-point inductor behavior (including steady-state short-circuit handling) is not implemented.
- Saved graph-bound DC operating points can be checked against caller-entered absolute voltage/current/power bounds, and graph-bound RC/RLC reports against sampled capacitor-voltage/inductor-current peaks; limits are not verified against component data and inter-sample peaks are not estimated. Component catalogue/datasheet qualification, free-text requirement interpretation, symbolic analysis, general-purpose or multi-objective optimization, and autonomous repair remain unimplemented. The RC synthesis slice performs only a bounded E-series R/C candidate search under its explicit cutoff constraint. The initial ESP32 output is a pin-mode scaffold only: it has not been compiled and includes no application behavior or board-level electrical verification. No values, models, pinouts, or provenance are silently inferred.
- GitHub Actions CI is configured for Ubuntu and Windows with Python 3.11/3.12, native CMake/CTest/self-test, Python tests, and JavaScript syntax; no hosted matrix result has been observed yet. No native install/package target, verified macOS build, benchmark suite, ABI compatibility matrix, cancellation/job queue, or comprehensive security review is in place.
- No vendor qualification, physical schematic verification, hardware testing, manufacturing checks, nonlinear/SPICE equivalence, or production-readiness claim is made.

## Environment notes

- CMake was installed into a temporary local virtual environment for validation; no runtime Python dependency was added.
- KiCad/ngspice and trusted manufacturer model corpora are not configured for this work. No external tool execution or datasheet qualification is implied by the native-core tests.
